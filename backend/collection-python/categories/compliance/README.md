# compliance

合规管理（系统稽核）采集脚本与配置目录。已发布版本保持不可变。

## 输入

`system_jhd_YYYYMMDD.txt`（月数据清单）：无表头、`@` 分隔、固定 27 列、UTF-8。
工单明细 `system_jhd_detail_*.txt` 是 31 列，**不属于本任务的输入**，文件名规则已排除。

## 取数口径

三列**直接取源列**，不做任何派生计算和聚合：

| 源列 | 下标(0基) | 目标字段 | 说明 |
| --- | --- | --- | --- |
| 稽核点编号 `check_code` | 3 | `metric_code` | 与平台 `metric_item.metric_code` 同名匹配 |
| 异常量 `abnormal_count` | 9 | `metric_value` | 十进制字符串，保留零值与原始精度 |
| 异常日期 `abnormal_date` | 8 | `data_time` | 三种形态，见下 |

## 异常日期规整

| 形态 | 出现场景 | 处理 |
| --- | --- | --- |
| `yyyyMMdd`（8 位） | 日频稽核点 | 当日 `00:00:00` |
| `yyyyMM`（6 位） | 月频稽核点 | 当月 `monthlyDay` 日（默认 1 日）`00:00:00` |
| 空 | 无异常的稽核点（异常量为 0） | 回退到文件名业务日，保留 0 值不丢指标 |

## 指标白名单

`config.json` 的 `metricCodes` 为平台 `metric_g1` 下已启用指标编码。
未在白名单内的稽核点会被跳过，跳过的编码写入 `skipped` 并在 stderr 明确输出；
不按名称相似自动匹配，也不因此让整批失败。

## 校验

以下情况明确报错、不静默通过：列数与 `expectedFields` 不符、稽核点编号为空、
异常日期非法、异常量非十进制或超出存储范围、同一指标编码与数据时间重复。
