# 第一层 · 专家基础权重

先读 [指标目录与增量筛选](references/catalog.md)，写入前读 [中转写入契约](references/write-contract.md)（仓库源码中为 `../write-contract.md`）。支持按系统 ID、大类 ID、小类筛选，未给范围时读取启用目录。仅分析时输出结果，不写入；收到提交要求后才写入。按真实指标 ID 和数据库中实际的小类划分工作。

1. 首次运行检查同组所有启用指标。已有专家审核后，只评估新增、尚未获得专家审核或定义发生实质变化的指标。仅当待审核建议同定义、未过期且审批快照与当前整组一致时跳过。定义摘要变化时核对具体差异，名称修正等不影响业务含义的改动可记录后跳过。
2. 结合指标定义、统计口径和有来源的业务资料，评估指标失常对客户、业务连续性和合规的影响。使用 1（一般）、2（重要）、3（关键）作为相对系数，逐项注明档位依据。短期告警数量、处理速度、点击次数只用于补充背景。资料不足时暂缓判断，列出所需资料。
3. 首版全组有依据时，按档位分配 100 个百分点。部分指标缺依据时，为未评估指标保留其当前合计百分点，将其余百分点按档位分给有依据的指标。增量时，仅用定义仍可比、当前原始系数为正且证据中保存了原档位的已应用指标做锚点。取「当前原始系数 ÷ 原档位」的中位数作为每档系数。以它乘此次新档位作为候选系数，其余指标沿用当前原始系数；全组归一后取评估对象的目标占比。两种方式均按中转契约预演审核实际结果，证据记录联动。锚点不足或预演不通过时交由人工定值。保留整组快照，明细只提交此次确实评估的指标。
4. 每个小类写一个 `expert_base` 批次，明细 `assessment=business_importance`。证据注明业务资料出处、定义摘要、档位、输入系数和归一化过程。推荐初版有效期 30 天，可由运行参数指定。
5. 返回写入的批次 ID、待审数量和跳过原因。正式权重由平台审核人应用。
