# 第三层 · 月度动态权重建议

先读 [月度数据读取口径](references/monthly-data.md) 和 [月度统计与建议规则](references/weight-rules.md)，写入前读 [中转写入契约](references/write-contract.md)（仓库源码中为 `../write-contract.md`）。支持按系统 ID、大类 ID、小类筛选，未给范围时读取启用目录。默认以北京时间上一个完整自然月为统计期，也可指定已结束的自然月，均与紧邻的前一个月比较。区间左闭右开。仅分析时输出结果，不写入；收到提交要求后才写入。

1. 按指标 ID 统计有效观测数、覆盖、缺失、趋势和持续异常。标明来源、样本量及统计口径。告警量按可核实的对象规模和事件去重口径解释。缺少影响范围、重复事件标识或 SLA 时，将相应字段标为缺失。若有点击数据，只描述关注度。
2. 先区分当前风险和持续的业务重要性变化。只有异常或风险证据时，提交 `current_risk`，建议占比沿用当前值，解释风险变化和数据限制。这类建议在平台只供参考。
3. 按规则对齐时间序列，用熵权法衡量区分度，用平台版 CRITIC 衡量变异及冗余。只有连续两个周期方向一致、数据质量达标，而且有独立的长期业务证据支持时，才产生 `business_importance` 建议。把统计信号作为 20% 的调整参考，其余沿用当前基础占比。执行单项限幅和全组归一化预演，把任何被动变化写进证据。
4. 每个小类写一个 `monthly_dynamic` 批次，保存月度区间、对比区间、数据来源、去重方式、数据缺口、长期影响证据及计算细节。同一指标只出一条建议，满足调权门槛时用 `business_importance`，其余有风险依据时用 `current_risk`。推荐生成后 30 天到期，可由运行参数指定。返回批次 ID 和数据缺口，后续由平台审核人处理。
